# 当たり判定シミュレーター

ゲームの「当たり判定」と「衝突応答（重なったら押し返す処理）」を、スマホで触りながら体感するための実験用ページ。

**公開URL: https://gyaruweijing-tech.github.io/Collision-Sim/**

> 初回アクセス時は物理エンジン（WebAssembly, 約1.2MB gzip）の読み込みで数秒かかります。

## 操作

| | |
|---|---|
| スマホ | 画面左下の仮想スティックをドラッグ。離すと止まる |
| PC | WASD / 矢印キー、スペースキーで発射 |

## 画面上部のボタン

| ボタン | 何が起きるか |
|---|---|
| **判定表示** | Rapierの`debugRender()`で、全オブジェクトの当たり判定を線で描く |
| **検知のみ** | 全オブジェクトをsensorに切り替える。すり抜けるが、重なりは検知されて光る |
| **すり抜け** | プレイヤーをkinematic bodyに切り替える。壁も敵もすり抜け、押し返されもしない |
| **撃つ** | 高速の弾を発射する（進行方向、止まっていれば正面） |
| **リセット** | 敵を配置し直し、プレイヤーを初期位置に戻す |
| **敵の数** | ランダムに動く敵8種の、各種類の個数（1〜5） |

## 置いてあるもの

### 見た目と判定が一致しているもの（青系・色分け）
球 / 箱 / カプセル / 円柱 / 円錐 / 凸包（ジェム）/ 雪だるま（球2個）/ ダンベル（球2個＋円柱）がランダムに漂う。
ピンクの**回るハンマー**（kinematic body）が3本、固定位置で回り続ける。
水色の**ドーナツ**はtrimesh判定なので、穴を本当にくぐれる。

### 見た目と判定がわざと違うもの（ピンク）
| 見た目 | 判定 | 体験できること |
|---|---|---|
| ドーナツ | 球 | 穴があるのに通れず弾かれる |
| 星型の板 | 箱 | 何もない角の部分に当たる |
| 細い棒 | 大きな球 | 約1.9m離れているのに当たる |

判定表示をONにして、水色のドーナツとピンクのドーナツを見比べるのが一番わかりやすい。

## 開発

```bash
npm install
npm run dev -- --host   # スマホから同一LANで開いて確認
npm run build
npm run preview
```

### 動作チェック

`tools/verify.mjs` は、この教材が主張している挙動を実際に物理ステップを回して確認する。

```bash
npm run build
npm run preview &
node tools/verify.mjs
```

trimeshドーナツを通り抜けられること、球判定ドーナツに弾かれること、星の箱判定・棒の球判定が効いていること、sensorモードで通り抜けつつ検知されること、すり抜けモードが本当にすり抜けること、接触で光ること、30秒放置して誰も場外に出ないこと、を検査する。

## GitHub Pages

`main` への push で `.github/workflows/deploy.yml` が走って自動公開される。

**初回だけ手動設定が必要**：リポジトリの Settings → Pages → Source を **「GitHub Actions」** にする。
ワークフローからは設定できないため、これを忘れるとデプロイが失敗する。

`vite.config.ts` の `base` はリポジトリ名と大文字小文字まで一致させること（`/Collision-Sim/`）。

## 技術メモ

- Vite + TypeScript / 描画 Three.js / 物理 Rapier（`@dimforge/rapier3d-compat`）
- 物理は1/60秒の固定ステップ。120Hz端末でも倍速にならないようアキュムレータで回している
- three.jsとRapierはサイズ引数の意味が違う（全長 vs 半分）ため、形状定義は `src/shapes.ts` に集約している
- 秘密情報は一切含まない
